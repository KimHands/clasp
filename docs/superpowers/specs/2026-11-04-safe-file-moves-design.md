# 파일 이동 안전 설계

개편 범위 B의 첫 번째 묶음이다. 나머지 묶음(전송 경계, 분류 품질, 빌드와 CI, 읽기 전용 MCP)은 별도 문서로 다룬다.

## 목표

어떤 실행 경로에서도 정리와 되돌리기가 사용자 파일을 덮어쓰거나 잃지 않는다. 이 성질을 테스트로 고정한다.

## 현재 문제

임시 폴더에서 실제 백엔드를 실행해 재현했다.

| 시나리오 | 현재 결과 |
|---|---|
| 덮어쓰기, 대상 파일이 이미 스캔됨 | 기존 파일이 사라지고 `/apply`가 500을 반환한다. 이동 로그가 남지 않아 Undo도 불가능하다 |
| 덮어쓰기, 대상 파일이 스캔 후 생김 | 기존 파일이 사라지고 Undo로 복구되지 않는다 |
| 정리 후 원위치에 새 파일 생성, 이후 Undo | 새 파일을 확인 없이 덮어쓴다 |
| 이동한 파일 일부를 지운 뒤 Undo | 1건이 실패해도 이력은 되돌림 완료로 표시된다 |
| 파일이 하위 폴더에만 있을 때 정리 | 스캔 루트가 아니라 공통 하위 폴더 안에 정리된다 |

코드를 읽어 확인한 위험도 있다.

- 존재 확인과 이동 사이에 대상 파일이 생기면 덮어쓴다(`shutil.move`).
- 스캔 루트 안의 폴더가 바깥을 가리키는 심볼릭 링크면 파일이 루트 밖으로 나갈 수 있다.
- 경로 범위 검사가 `startswith`라 `/a/b`와 `/a/bc`를 구분하지 못한다.
- 이동 도중 프로세스가 죽으면 무엇이 움직였는지 기록이 없다.

## 결정

### 덮어쓰기 제거

충돌 처리는 `rename`과 `skip`만 남긴다.

- `POST /apply`는 `overwrite`를 `INVALID_TYPE`(400)으로 거부한다.
- Apply 화면의 선택지에서 뺀다.
- 과거 이력을 표시할 수 있도록 `RESOLUTION_LABELS`의 `overwrite` 라벨은 유지한다.

### 이동 원자 연산

`services/safe_move.py`에 `move_no_clobber(src, dst)`를 둔다. 대상이 이미 있으면 `FileExistsError`를 내고 아무것도 바꾸지 않는다.

1. `os.link(src, dst, follow_symlinks=False)`로 대상을 만든다. 대상이 있으면 운영체제가 거부한다.
2. `os.unlink(src)`로 원본 이름을 지운다.
3. 하드링크를 지원하지 않는 파일시스템이면 `O_CREAT | O_EXCL`로 대상 자리를 먼저 확보한 뒤 `os.replace(src, dst)`로 옮긴다.
4. 볼륨이 다른 경우(`EXDEV`)는 지원하지 않고 실패로 기록한다. 대상은 항상 스캔 루트 안이므로 드문 경우이고, 복사 후 삭제 경로를 더하는 비용이 더 크다.

`shutil.move`는 이동 코드에서 쓰지 않는다.

### 이동 전 기록

파일 하나의 처리 순서는 다음과 같다.

1. `action_type="pending"` 로그를 커밋한다.
2. `move_no_clobber`를 실행한다.
3. 로그를 `move`로 바꾸고 `File.path`를 함께 커밋한다.
4. 2에서 예외가 나면 로그를 `failed`로 기록하고 다음 파일로 넘어간다.
5. 3에서 예외가 나면 파일은 이미 옮겨졌으므로 롤백하고 로그를 `pending`으로 남긴 채 실패로 집계한다. 다음 시작 때 복구 절차가 `move`로 확정한다.

파일 하나의 실패로 요청 전체가 500이 되지 않는다.

앱 시작 시 `recover_pending()`이 남은 `pending` 로그를 실제 파일과 대조한다.

| 원본 | 대상 | 판단 | 처리 |
|---|---|---|---|
| 없음 | 있음 | 이동 완료 | `move`로 표시하고 `File.path` 갱신 |
| 있음 | 없음 | 이동 안 됨 | `failed`로 표시 |
| 있음 | 있음, 같은 inode | 링크 직후 중단 | 대상 링크만 지우고 `failed`로 표시 |
| 있음 | 있음, 크기 0, 다른 inode | 자리 확보 직후 중단 | 대상만 지우고 `failed`로 표시 |
| 있음 | 있음, 그 외 | 판단 불가 | 파일은 건드리지 않고 `failed`로 표시 |
| 없음 | 없음 | 외부에서 삭제됨 | `failed`로 표시 |

### 대상 경로 점유 판단

`_resolve_conflict`는 디스크 존재 여부에 더해 다른 `File` 행이 그 경로를 쓰고 있는지도 본다. 디스크에 파일이 없어도 오래된 행이 경로를 잡고 있으면 `files.path` 유니크 제약에 걸리기 때문이다. 점유된 경로는 `rename`이면 번호를 붙이고 `skip`이면 건너뛴다. 미리보기의 충돌 판단도 같은 함수를 쓴다.

### 정리 기준 폴더

`_find_common_base` 추측을 없애고 요청의 `folder_path`를 기준으로 삼는다.

- `/apply/preview`에도 `folder_path`를 필수로 받는다. 미리보기와 실제 이동의 기준을 같게 하기 위해서다.
- `realpath`로 정규화한 뒤 스캔과 같은 허용 범위(홈 아래) 검사를 적용한다. `_validate_folder_path`를 라우터에서 공용 위치로 옮긴다.
- 모든 대상 파일이 기준 폴더 안에 있어야 한다. 하나라도 벗어나면 이동 전에 요청 전체를 `PERMISSION_DENIED`로 거부한다.
- 범위 검사는 `os.path.commonpath`로 한다.
- 대상 디렉터리는 만든 뒤 `realpath`로 다시 확인한다. 심볼릭 링크로 기준 폴더를 벗어나면 그 파일을 `failed`로 기록한다.

### 되돌리기

- 원위치에 파일이 있거나 다른 `File` 행이 원위치 경로를 쓰고 있으면 옮기지 않고 `source_occupied`로 보고한다.
- 되돌리기 이동도 `move_no_clobber`를 쓴다. 이동 직후 `File.path`와 `is_undone`을 한 번에 커밋한다. 이 커밋이 실패하면 파일은 원위치에 있고 로그는 되돌리기 전 상태로 남으며, 재시도 때 `source_occupied`로 보고된다. 파일 손실은 없다.
- `ActionBatch.is_undone`은 모든 `move` 로그가 되돌려졌을 때만 참이 된다.
- 실패한 항목은 같은 `action_log_id`로 다시 시도할 수 있다.

### 이력 상태

`GET /apply/history` 응답에 로그에서 계산한 `undo_state`를 더한다.

| 값 | 조건 |
|---|---|
| `none` | 되돌린 로그가 없다 |
| `partial` | 일부만 되돌렸다 |
| `undone` | 모두 되돌렸다 |

기존 `is_undone` 필드는 유지한다.

### 프런트엔드

- Apply 화면은 `undo_state`로 표시하고, `partial`이면 "일부 되돌림"과 다시 시도 버튼을 보여 준다.
- `applyStore`는 Undo 후 무조건 `is_undone: true`로 바꾸지 않고 이력을 다시 불러온다.
- `source_occupied` 사유를 사용자 문구로 표시한다.
- 미리보기 호출에 `folderPath`를 넘긴다.

### DB 스키마

변경하지 않는다. `action_type`은 자유 문자열이라 `pending`을 추가해도 마이그레이션이 필요 없고, `undo_state`는 저장하지 않고 계산한다.

## 범위 밖

- 재스캔 시 수동 분류와 규칙이 화면에 반영되지 않는 문제: 분류 품질 묶음에서 다룬다.
- 실행 중 다른 프로세스가 파일을 바꾸는 경우의 내용 일치 검증: 대상을 덮어쓰지 않으므로 손실 경로가 아니다.
- 서비스 함수의 비동기 전환: 이동이 오래 걸리면 이벤트 루프를 막는 문제는 남는다. 손실과 무관하므로 빌드와 CI 묶음 이후에 판단한다.
- 볼륨 간 이동.

## 테스트

`backend/tests/`에 pytest를 추가한다. 실제 파일을 임시 폴더에서 옮기고, DB는 테스트마다 임시 SQLite를 쓴다. 임베딩 모델은 불러오지 않는다. 고치기 전에 각 테스트가 실패하는 것을 먼저 확인한다.

- `move_no_clobber`: 정상 이동, 대상 존재 시 양쪽 파일 불변, 하드링크 불가 시 대체 경로, 심볼릭 링크 파일을 링크째로 이동.
- 정리: 대상 점유 시 `rename`과 `skip`, 오래된 `File` 행이 점유한 경로, `overwrite` 거부, 낮은 신뢰도 파일 제외, 기준 폴더 이탈 거부, 심볼릭 링크 폴더로 이탈한 파일 `failed`, 파일 하나의 실패 후 나머지 진행.
- 되돌리기: 원위치 점유 시 `source_occupied`와 파일 불변, 일부 실패 시 `partial`, 재시도 후 `undone`.
- 복구: 위 복구 표의 모든 행.
- 불변식: 위 시나리오를 실행한 뒤 시작 시점 모든 파일의 해시가 어딘가에 그대로 남아 있다.
- 프런트엔드: 앱을 실행해 충돌 모달에 덮어쓰기가 없고 일부 되돌림이 표시되는지 확인한다.

## 완료 기준

- 위 테스트가 모두 통과한다.
- "현재 문제" 표의 재현 시나리오를 실제 백엔드로 다시 돌렸을 때 파일 손실이 없다.
- `docs/API_명세서.md`의 `conflict_resolution`, 미리보기 파라미터, 이력 응답을 코드와 맞춘다.
